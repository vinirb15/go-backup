# Templates de Issue

Todo conteúdo da descrição usa **lista alternada**: campos e itens alternam entre `-` e `1.` sem blocos de prosa.

---

## Task / Feature

```
## Contexto
- **Motivação:** [breve descrição do problema ou necessidade]
1. **Cenário atual:** [o que acontece hoje / o que falta]
- **Impacto:** [impacto no usuário ou no negócio]

## Objetivo
1. **O que:** [o que precisa ser feito]
- **Por quê:** [razão ou justificativa]
1. **Entregável esperado:** [saída tangível e verificável]

## Critérios de Aceitação
- [ ] Dado [contexto], quando [ação], então [resultado]
- [ ] Dado [contexto], quando [ação], então [resultado]
- [ ] Dado [contexto], quando [ação], então [resultado]

## Notas Técnicas
1. **Arquivos afetados:** [caminho/arquivo.ts]
- **Dependências:** [libs, serviços, outros módulos]
1. **Considerações:** [observações técnicas relevantes — opcional]
```

---

## Bug

```
## Descrição do Bug
- **Resumo:** [o que está acontecendo de errado]
1. **Severidade:** [crítico / alto / médio / baixo]
- **Ambiente:** [produção / homologação / local]

## Comportamento Atual
1. [Descrição do comportamento atual observado]

## Comportamento Esperado
- [Descrição do comportamento esperado]

## Passos para Reproduzir
1. [Passo 1]
- [Passo 2]
1. [Passo 3]

## Arquivo / Linha Afetado
- `caminho/do/arquivo.ts:linha`

## Notas Adicionais
1. **Logs / Evidência:** [cole o erro ou link para screenshot]
- **Contexto adicional:** [opcional]
```
